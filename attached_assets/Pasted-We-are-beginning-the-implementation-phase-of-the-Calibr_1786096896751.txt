--------------------------------------------------
IMPLEMENTATION DECISIONS
--------------------------------------------------

For this MVP, use these decisions unless the contract has since been explicitly updated:

1. Input length:
- enforce 4,600 words as the current production limit
- do not silently truncate
- return NOTES_TOO_LONG when exceeded

2. PDFs:
- support text-based PDFs through pdfplumber
- do not add OCR
- scanned/image-only PDFs return UNSUPPORTED_PDF

3. Model:
- preserve Qwen/Qwen2.5-7B-Instruct as the current baseline
- make the model configurable through HF_MODEL
- do not change the prompt/model merely because another option exists

4. Service security:
- prepare FastAPI for server-to-server authentication using ML_SERVICE_API_KEY

5. Upload path:
Browser
→ Next.js
→ FastAPI

The browser must never call FastAPI or Hugging Face directly.

6. Question count:
- default 6
- allow requested_count from 1 through 10
- the model may return fewer questions if the material does not support the requested amount

7. MCQ:
- exactly four answer_choices
- answer must exactly match one of the choices

8. Truncated/invalid generation:
- do not return partial malformed generations as success
- fail with a structured generation error

9. Evaluation:
- llm_judge_eval.py and human evaluation scripts remain offline/dev-only
- they must not run in the synchronous student generation request

--------------------------------------------------
FASTAPI ENDPOINT 2
--------------------------------------------------

Implement:

POST /parse-pdf

Request:

multipart/form-data

file:
PDF binary

Behavior:

1. validate file is a PDF
2. extract text using pdfplumber
3. normalize the extracted text
4. compute word_count
5. compute approx_token_count using the currently established approximation
6. preserve file_name
7. reject empty/unreadable PDFs
8. reject scanned/image-only PDFs cleanly

Success response:

{
  "text": "...",
  "word_count": 1234,
  "approx_token_count": 1641,
  "file_name": "chapter5.pdf"
}

Use the exact field names from the integration contract.

Do not return:

filename

or:

approx_tokens

because the actual established field names are:

file_name
approx_token_count

--------------------------------------------------
PDF ERROR BEHAVIOR
--------------------------------------------------

Return structured errors.

Examples:

PDF_PARSE_FAILED

UNSUPPORTED_PDF

Do not silently skip unusable PDFs as the old CLI script did.

Student-safe example:

{
  "success": false,
  "code": "UNSUPPORTED_PDF",
  "message": "This PDF appears to be scanned. Please use a text-based PDF or paste your notes."
}

--------------------------------------------------
WORD LIMIT
--------------------------------------------------

Before calling the model:

count words using the agreed MVP rule.

If:

word_count > 4600

return:

{
  "success": false,
  "code": "NOTES_TOO_LONG",
  "message": "Your notes are too long. Please use one lecture, chapter, or study section at a time."
}

Do NOT silently truncate the notes.

--------------------------------------------------
STRUCTURED QUESTION SCHEMA
--------------------------------------------------

Every returned question must use exactly:

{
  "type": "...",
  "question": "...",
  "answer": "...",
  "answer_choices": [],
  "source_excerpt": "..."
}

Supported type values:

active_recall
mcq
feynman
fill_in_blank

All five fields are required.

--------------------------------------------------
QUESTION VALIDATION
--------------------------------------------------

Before FastAPI returns success:

Validate every generated question.

For ALL types:

- type must be supported
- question must be non-empty
- answer must be non-empty
- answer_choices must be an array
- source_excerpt must be non-empty

For MCQ:

- answer_choices must contain exactly 4 non-empty strings
- answer must exactly match one of answer_choices

For non-MCQ:

- answer_choices must equal []

If model output is malformed:

do not pass raw model output through as success.

Return:

INVALID_MODEL_RESPONSE

--------------------------------------------------
SOURCE EXCERPT
--------------------------------------------------

Preserve source_excerpt.

It should represent supporting/verbatim material from the supplied notes according to Shreya's prompt contract.

Do not drop this field.

The Question Bank will later use this for grounding/review.

--------------------------------------------------
GENERATION RESPONSE
--------------------------------------------------

Success:

{
  "questions": [
    {
      "type": "active_recall",
      "question": "...",
      "answer": "...",
      "answer_choices": [],
      "source_excerpt": "..."
    }
  ]
}

The response may contain fewer than requested_count if the source material does not support enough valid questions.

Do not fabricate extra questions merely to hit the requested count.
